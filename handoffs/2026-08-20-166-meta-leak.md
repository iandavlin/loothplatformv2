## What was wrong, in one line

A profile's `<meta name="description">`, `og:description` and
`twitter:description` published the member's one-line "what you do"
(`users.at_a_glance`) **verbatim to crawlers, logged-out visitors and link
unfurls**, while the rendered body correctly withheld it behind the members
gate. **42 members on live, 28 on dev2.**

## The measurement that decided the ruling

The issue filed this as needing Ian's choice between two coherent positions
(honour visibility, or accept the meta as public). **It was not a choice.**

> Of live's 42 leaking members, **ZERO had ever chosen members-only.**
> `header_vis_explicit` is false for all 42.

`Block::HEADER_DEFAULT` is `'members'` and 1,917 of 1,933 members have never
opened that setting. So nobody hid this text and nobody published it — the head
and the body simply disagreed about what an untouched default meant. That is a
defect, and Ian ruled "Fix meta leak."

**If you are tempted to reopen the policy question, re-run that query first.**
It is the whole argument.

## The fix

`u.php`'s SEO block already opened by explaining that location is omitted from
the head because `location_visibility` is members for nearly everyone, *"so
surfacing it in the public head would leak a members-only field."* `at_a_glance`
sat two lines below under the same default. The reasoning was written down; it
had not been applied to the field beside it.

```php
$seoGlance = Block::headerCeiling($subjectId) === 'public' ? <glance> : '';
```

Three lines in `u.php`, three in `p.php`. `Block::headerCeiling()` is the
**body's own rule, called** — not reimplemented. Anything but `public` fails
closed. The public-safe generic branch already existed for members with no
one-liner, so this only changes WHICH members reach it.

### `/p/` was the same defect, and worse per page

Practice `tagline` **and** `about` under `PRACTICE_HEADER_DEFAULT = 'members'`,
and `about` is the long field. 3 practices on each box. Found while measuring
the profile leak; Ian ruled 8/20 to fix both in this lane. Same shape, via
`Block::practiceHeaderCeiling()`.

## Why it is UNFLAGGED (Ian approved this reasoning, 8/20)

The flag law exists because dev2 serves main, so member-facing work cannot be
verified before merge and reaches Ian as a production defect. **Here the risk is
inverted: the OFF state IS the leaking state.** A flag defaulted OFF merges a
fix that does nothing while 42 members stay indexed.

The change adds no surface and no state — it swaps a private string for a
generic one already shipping to glance-less members. Worst case if the test were
wrong in the strict direction is a public-header member getting a generic
snippet: an SEO regression, visible and reversible in one line, never a leak.
Precedent: `789b480`, the contrast fix — member-facing, keeper's call, unflagged
because it strictly repaired a measured defect.
