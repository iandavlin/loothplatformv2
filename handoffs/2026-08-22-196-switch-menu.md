## Why a capability, and why nothing new was invented

The shared header renders on **seven apps under seven unix users with no
database**, so it cannot ask about Patreon itself. `capabilities` is the channel
that already answers per-viewer questions for it — it is how `stripe_testgroup`
reaches this same menu — so `patreon_paying` rides it. No new store (the
tester-unlock JSON store exists for the **anonymous** case, which has no
per-viewer channel; this viewer is signed in). No new detection: `PatreonStanding`
is the one definition #150's three doors ask.

Cost: `wp_user_id` is the **PRIMARY KEY** of `lg_patreon_members` (1,704 rows), so
it is one PK read on a path that already makes a loopback HTTP call. Computed
**unconditionally**, not narrowed to the cohort — a capability whose `false` means
two different things is exactly the trap that cost a day on 8/16. Fails closed to
`false` = Join = today.

⚠️ **Gate 34b already cross-checks the pass-through**, so forgetting the far end
is a RED, not a silent false. That failure happened on 8/16 — to
`stripe_testgroup`, to this menu, to **this same member**.

## ⚠️ The account menu is DESKTOP-ONLY. Presence-is-not-reachability, fourth instance.

Measured three independent ways on 8/22, signed in as 1953: on **`/hub/`**, on the
**front page**, and on the branch preview, at **390 and 640 the account chip is
`display:none`** and `#lg-account-menu` is `display:none`. Below 641 the menu is
in the DOM the whole time and **is not a door at all**.

`bottom-nav.js`'s account-sheet row existed precisely BECAUSE the pill was in the
DOM (it reads the href with `getAttribute`, which works on a hidden element). So
removing the pill on its own would have left a signed-in tester **no join or
switch door on a phone, on any surface**. The row now mirrors the **menu entry**
through `.lg-chrome__menu-join` — the `.lg-chrome__menu-signin` shape that file
already uses — and reads **both** the href and the label from it, because since
#196 the word itself varies. One door, in the account menu, drawn on a phone in
the sheet that IS the account menu on a phone. Keeper confirmed this reading
before it was built.

## ⚠️ DECLARED CONFIG COUPLING — a `git pull` does NOT deliver this

A new slug means the location regex in all three
`platform/nginx/strangler-membership*.conf`; **there is no catch-all**. And the
running snippet is a **root-owned COPY, not a symlink**:

```
sudo cp platform/nginx/strangler-membership.conf /etc/nginx/snippets/ \
  && sudo nginx -t && sudo systemctl reload nginx
```

Without it, Switch is wired perfectly and lands on a WordPress 404. Gate 93 §E
asserts the three-file agreement **unconditionally**, reports the box gap and
names that command, and proves the page routable through the lane preview
meanwhile — so *held* never means *unmeasured*.

⚠️ Separately, **reported not fixed**: that box copy is already **behind the
repo** — missing the tracked `fastcgi_param LG_FOLLOWING_CADENCE 1`.
