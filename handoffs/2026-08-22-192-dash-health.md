## What shipped

A **Health** tab on the LG Member Sync dash, second after Settings, answering
the five questions the charter asked plus one the charter implied:

1. **Are webhooks arriving** — last verified event and its age, signature
   failures, and the two facts that make the verdict trustworthy.
2. **Do the two halves agree** — `lgms_shared_secret` vs `LGMS_SHARED_SECRET`,
   `lgms_stripe_webhook_secret` vs `STRIPE_WEBHOOK_SECRET`.
3. **Test or live mode** — both sides, plus `APP_DEBUG`.
4. **Does the catalogue resolve to tiers** — and how many products carry no ref.
5. **Who may buy** — audience, cohort size, and the page-gate partners.
6. **Can the two halves reach each other** — sync URL vs this site, BuddyBoss's
   restriction, and a live loopback probe.

Three files do the work: `Membership\Health` (reads, prints nothing),
`HealthPanel` (renders, decides nothing), and `LGSB\Core\WebhookReceipts` (the
data source question 1 did not have).

## Decisions worth not re-deriving

- **The `.env` is read off disk, not asked for over HTTP.** The one moment this
  panel matters is when a channel is broken, and an HTTP answer goes UNKNOWN
  exactly then. It also sidesteps a chicken-and-egg: the natural way to
  authenticate such a call is the shared secret, which is under test.
- **A secret cannot reach the screen even by mistake.** `envFacts()` reduces
  every secret-shaped key to present/length/sha256 as it parses; the sha is
  consumed by `hash_equals` and never returned; the Stripe key prefix is
  collapsed to `test`/`live`/`unknown` before crossing the boundary. Ian's rule
  is a property of the data, not a discipline the renderer must remember.
- **audit_log, not a new table.** It already names `'webhook'` in its own
  `actor_type` comment, has no FK on `subject_id`, indexes `(action,
  created_at)`, and held zero rows on both boxes. **No migration ⇒ no live DDL
  for Ian**, which is what lets this land before go-live rather than after
  another hand-off.
- **Signature failures are throttled to one row per five minutes.** That
  endpoint is unauthenticated; an unconditional insert is a table anyone can
  fill. Verified events are Stripe-signed and recorded unconditionally.
- **Raw curl with `CURLOPT_RESOLVE`**, per this plugin's own CLAUDE.md
  (*"wp_remote_post does NOT work for these"*). The URL keeps the real hostname
  so SNI, the cert and nginx's `server_name` still match; only the connection is
  pinned to loopback, so Cloudflare's 403-that-looks-like-an-outage can't happen.

## Three things the build itself taught

1. ⚠️ **The first real run against dev2 produced a FALSE ALARM in the panel.**
   *"A payment completed with no webhook recorded"* fired against 109 customers
   and subscriptions that all predated the recorder. A panel that cries wolf on
   its own deployment day is one nobody reads twice. *Since recording started*
   is now the recorder file's own mtime on the box — readable rather than
   assumed, and it errs only towards silence. History is counted separately and
   labelled; with no recorder found the answer is `unknown`, not a guess.
2. ⚠️ **PHP's `file_get_contents()` on a directory returns the empty string,
   not false.** So a path pointing at a directory was reported as *"a truncated
   deploy"*. Caught by gate 91's fixture, not by review.
3. ⚠️ **Three assertions were the same assertion wearing two names**, all found
   by red-first rather than reading: renaming the tab slug left §H1 green off
   the dispatch one line away; relabelling the copy button left §H6 green off
   the panel's own clipboard JS; deleting one env-var reader left §H16 green off
   an unrelated one in the neighbouring method.
