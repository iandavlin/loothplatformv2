## Why the rename is right, and it is the panel's own words

The other two positions name an AUDIENCE. **Me** looked like a third audience and
is not one — it is the working view, and the panel's own hint already says *"This
IS your editor."* `view=me` **is** edit mode: `$editing = ($isOwner && $role ===
'me') || $adminEditing` (`u.php:127`), same on `p.php:50`.

## ⚠️ The label moved and the value did not — and that is the whole risk

Every consumer keys on the **value** `me`; **nothing anywhere reads the visible
text**. Verified before touching anything: no gate, no test, no CSS selector, no
stored preference. `grep` of `tools/gates/` for `view=me`, `lg-viewas` and
`"View as"` returned **nothing** — the surface had **no gate at all**.

So gate 97 asserts a **pair per position**: the text is the new label **and** the
href/value still says `me`. Asserting only the text goes green on the one change
that costs members their editor — someone "tidying" `?view=me` to `?view=edit`.

### ⚠️ A DEPLOY GAP IS NOT A DEFECT, and this gate refuses to score it as one

The bare serve renders whatever `~/loothplatformv2-clean` has **pulled**, which
lags main after every merge. A gate that went RED on a label because dev2 had not
pulled yet would stop **every lane**. So on the shared serve a text disagreement
is **NO VERDICT** naming the gap; on a lane preview — which serves this worktree
directly — the same disagreement is a **finding**. The href, aria-current and
behaviour legs score on both, because they read identically before and after
#195 and therefore cannot be a deploy gap. Exit stays 0, and the summary line
says **"GREEN ON SOURCE — the RENDERED half was NOT scored"** so it can never be
mistaken for a verified serve.

## Five gate/harness defects found while building — all mine, all in known families

1. **`"lg-shell--owner" in html` was the LIVENESS check.** That string is a **CSS
   rule five times over in the same response**, so it was true of a page whose
   body is plain `class="lg-shell"` — vacuous on a signed-out render, and it
   *manufactured* a finding that `?view=member` renders edit chrome. Style and
   script are stripped now and the class is read off the **element**.
2. **Attributes parsed with `<a(.*?)>`** — which stops at the `>` inside `?>`, so
   every position's "text" came back as a slab of PHP and six legs went RED
   against a correct tree. PHP tags are masked before parsing.
3. **Positions matched by DOM order.** `_render.php` lists them
   `me/member/public` — the reverse of the other two — so it scored three
   findings about a correct file.
4. **The value check was an `any()` of the shapes**, so *half* a rename passed:
   rewriting `viewLink('me')` left `$role==='me'` behind and §A called it intact.
   Two mutations were saved only by §B, which needs a live surface — the half
   meant to be honest with no server was blind to the very failure it exists for.
   A third (`data-role`) got through entirely. Found by red-first m04/m05/m06.
5. **The seg selector demanded the opening tag verbatim**, so a no-op control
   mutation adding one space made the gate announce the switcher had vanished.

**And one about the surface itself:** `/p/` asked cold renders the **non-owner**
page (52KB vs 104KB) because only `/u/` performs the invisible `looth_id` mint
hop through `/looth-auth/issue`. The gate warms on `/u/` first; without it the
seg's own **stylesheet** answered for its **markup**.
