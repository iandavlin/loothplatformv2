Featured members — your picks stay up, and the band is never empty

You said: “The changes made to featured member has removed members from the front page. The override I wanted would still have them on the frontpage even if they didn’t meet the criteria.” You were right, and it is worse than one thing going wrong — there are two, and the stopgap I was handed for you could never have worked. Everything below is measured on live, not guessed.

The stopgap is withdrawn. Turning the flag off would not have brought the band back. Nothing on the box actually reads the override file it was supposed to go in, and even if it did, the code takes the band down when the flag is off and a member is selected — measured: flag on renders one band, flag off renders none. So there was never a switch to flip. The repair is the two halves below.

Half one — one command from you, and it is not the feature’s fault

The front page reads member details out of the profiles database under a narrow permission list. One column was added to that list in the code on 20 August and the matching permission was never granted on live. Without it the database refuses the read, the page quietly gives up, and the band disappears for everyone, no matter who you pick. This one command fixes that half — it is a live write, so it is yours:

sudo -u postgres psql profile_app -f tools/cut/featured-member-grants.sql

What a pinned pick looks like — your man, on the front page

Pinning drops the tick requirement and the “must have a line of text” requirement. It prints only what their profile already shows the public, so nothing private leaks: photo, name, and a link. No line of text is better than no card.

One thing I need a yes or no on

Pinning skips every criterion except one: a member who has set their whole profile to Private. That is not a completeness bar, it is them saying “I am not public”, and pinning them would put their face on the open web pointing at a page the public cannot open. It is exactly one member on each box today. My recommendation is to keep that one refusal and show it in the dash as “cannot be pinned — their profile is Private”.
