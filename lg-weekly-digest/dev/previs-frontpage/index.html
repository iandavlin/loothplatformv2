Front page: the latest weekly email, for logged-out visitors

Backlog #8. Shown only when signed out — members already get the email.

The one thing to decide: do we show the issue's contents as normal front-page cards (A, my recommendation), or the actual email in a frame (B)?

A — RECOMMENDED the issue, rendered as our own cards

DESKTOP
PHONE · 390px

Why I recommend it. It is built from the same issue data the email is (latest_sent_issue_id() + get_data()), but drawn with the front page's own type and colours. So it resizes properly, reads the same on a phone, and follows dark mode — none of which an email can do, because an email is a fixed-width document with its own light-only styling baked in.

It is also nearly weightless: text and links, no images, no second document to load.

B — ALTERNATIVE the actual email, in a frame

DESKTOP
PHONE · 390px

Why I did not pick it. It shows the literal thing you are signing up for, which is a real advantage. But it is the same pattern you have already objected to on the signup page: an email designed for a wide screen squeezed into a narrow box. On a phone it lands in about 300px and gets cramped, and it cannot follow dark mode — the email is light-only by design, so it would sit as a white rectangle on a dark front page.

Straight about one thing: I still do not know what you saw on the signup page. I measured it at ten screen sizes and never reproduced the sideways movement. That is exactly why I am not recommending we put the same frame on the front page as well.
